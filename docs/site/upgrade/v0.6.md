# Upgrading to v0.6

v0.6 removes the names v0.5 deprecated. A project that uses none of
them (your editor and `staticcheck` mark them) needs no change in its
code; its settings, command names and process types may still need one
(below).

Upgrade in this order. `go fix` rewrites the old names only while they
still exist, so it runs on v0.5, before the upgrade:

1. On v0.5 (`v0.5.x`), run `go fix ./...`. It rewrites most of the
   names below. Then rename by hand what it leaves (the
   [calls it can't rewrite](#what-go-fix-doesnt-rewrite)).
2. Rename the [settings](#settings-renamed-in-v05-are-no-longer-read)
   in your `.env` files and your deployment's environment.
3. Update the modules: `go get anetos.dev/anetos@v0.6.0`, the tool
   (`go get -tool anetos.dev/anetos/cli/cmd/anetos@v0.6.0`), `admin`
   and the drivers you use to their v0.6.0; then `go mod tidy`.
4. Run `go tool anetos check`. The compiler names any old name left.

## What go fix doesn't rewrite

`go fix ./...` (Go 1.26 and later) leaves these alone, and they don't
build on v0.6:

- **Calls of generic functions whose type arguments are inferred:**
  `auth.ForApp(app, users)`, `social.ForApp(…)`, `ai.Func(…)` and
  `admin.UserName(…)`. Go's inliner doesn't rewrite them yet; rename
  them by hand. (`db.PruneTrashed[T]` and `admin.Field[T]`, always
  written with their type argument, are rewritten, `admin.Field`'s
  arguments swapped for `admin.TextColumn`.) Check an
  `auth.ForApp[*User](…)` with its type argument written out after
  `go fix`: Go 1.27.2's inliner rewrites it into code that doesn't
  compile (`auth.Users[**User]`); write `auth.New(app, users)`.
- **The error variables** `auth.ErrNoUser` and `auth.ErrNoPendingSignIn`
  (a variable can't be inlined): use `auth.ErrUserNotFound` and
  `auth.ErrNoPendingLogin`.
- **Methods of generic types:** `a.SignIn`, `a.SignOutOthers`,
  `a.SignOutEverywhere`, `a.CanTwoFactor`, `a.CanRemember`,
  `a.CanSignOutEverywhere` and `a.ActAs` (`auth.Auth[U]`), and
  `page.HasMore()` (`db.Page[T]`). The
  [v0.5 guide's commands](v0.5.md#logging-in) rename the `auth` ones.
- **Fields:** gemini's `Options.Config` and storagetest's
  `Features.SignedURLs`.
- **Methods your types implement.** These don't fail to build: the
  framework stops calling them, so v0.6 reports them instead.
  - A storage backend with `SignedURL` and no `TemporaryURL`:
    `TemporaryURL` fails with `has SignedURL, renamed TemporaryURL in
    v0.5`. Rename the method.
  - A user model with `CommunicationLocale` and no `PreferredMailLocale`:
    `i18n.ForUser` logs an error once and uses the display locale.
    Rename the method.
  - A plugin with `Listen` and no `Listeners`: `ext.Load` fails with
    `it has Listen, renamed Listeners in v0.5`. Rename the method.

## Settings renamed in v0.5 are no longer read

v0.5 read these settings under their former names too, with a warning.
v0.6 doesn't. If a former name is set and its new name isn't, the service
that reads it refuses to start, naming the new one:

```text
config: DB_CONNECTION (Config.Driver): renamed DB_DRIVER, and the former name is no longer read: rename it in your settings
```

So an app can't silently fall back to a default, such as SQLite for the
database. With both names set, the new one is used, and `doctor` says to
remove the former.

| Former name | Name |
|---|---|
| `DB_CONNECTION` | `DB_DRIVER` |
| `DB_DATABASE` | `DB_NAME` |
| `DB_USERNAME` | `DB_USER` |
| `MIGRATE_ON_RUN` | `DB_MIGRATE_ON_START` |
| `MIGRATE_READINESS` | `DB_MIGRATE_READINESS` |
| `SEARCH_LANGUAGE`, `SEARCH_RANKING` | `DB_SEARCH_LANGUAGE`, `DB_SEARCH_RANKING` |
| `CACHE_STORE` | `CACHE_DRIVER` |
| `SESSION_LIFETIME`, `SESSION_MAX_LIFETIME` | `SESSION_TTL`, `SESSION_MAX_TTL` |
| `AUTH_REMEMBER_LIFETIME` | `AUTH_REMEMBER_TTL` |
| `QUEUE_POLL` | `QUEUE_POLL_INTERVAL` |
| `LOCALE_URL` | `APP_LOCALE_STRATEGY` |

The [v0.5 guide's command](v0.5.md#settings-with-one-name-per-idea)
renames them in your `.env` files. Rename them in your deployment's
environment and secrets too, and the keys of another database
connection by hand: they keep its prefix (`ANALYTICS_DB_CONNECTION` is
`ANALYTICS_DB_DRIVER`).

A setting of your own renamed with a `was` tag still works as before:
the former name is read, with a warning. `was:"OLD,removed"` is the new
form for a former name you stop reading.

## Commands, process types and a rule

The names before v0.5 are refused with an error naming the one to use
(a command exits with status 2, `run` with status 1):

| Before v0.5 | Use |
|---|---|
| `./app routes:list` | `./app route:list` |
| `./app plugins:list`, `./app plugins:env` | `./app plugin:list`, `./app plugin:env` |
| `./app lang:check` | `./app locale:check` |
| `./app schedule:run <task>` | `./app schedule:test <task>` (`schedule:run` takes no arguments) |
| `go tool anetos lang:add`, `add lang` | `go tool anetos locale:add` |
| `go tool anetos make:admin:resource` | `go tool anetos make:admin-resource` |
| `run --only=http`, `workers`, `listeners` | `run --only=web`, `worker`, `listener` |
| `anetos.ProcessTypes("workers")` and the others, `app.Run(ctx, "http")` | `"worker"`, `"web"`, `"listener"` |
| The validation rule `unique_live` | `unique_without_trashed` |

Check your deploy files too: a Procfile, a systemd unit, a Kubernetes
manifest or a cron line may still name an old command or process type.

## The tool and projects made before v0.5

`anetos` no longer adds `views/ui` to a web project that has none.
v0.5's projects have it, but if yours was removed, `make:crud` and
`make:auth` stop and write nothing. `go tool anetos css:use <css
framework> --force` writes one. The tool no longer reads
`views/ui/kit.json`, the record of v0.5's development builds;
`views/ui/css.json` replaced it. And `go tool anetos generate` no
longer treats a `models_gen.go` that starts with the header before v0.5
(`// Code generated by anetos gen.`) as its own: it neither rewrites
nor removes it. Delete such a file and run `generate` again.
