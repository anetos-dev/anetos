# Upgrading to v0.3

v0.3 is in progress; this page grows with it. So far it covers the
rename.

## The framework is now Anetos

The working codename Anetos became **Anetos** (design D185). Every name
the framework owns changed with it, so an app built on v0.2 needs these
steps.

| Was | Is |
|---|---|
| module `anetos.dev/anetos` | `anetos.dev/anetos` |
| command `anetos` (`go tool anetos`) | `anetos` (`go tool anetos`) |
| package `anetostest` | `anetostest` |
| package name `anetos` (`anetos.App`) | `anetos` (`anetos.App`) |
| `//anetos:model`, `//anetos:skip` | `//anetos:model`, `//anetos:skip` |
| `-- anetos:no-transaction`, `-- anetos:no-split` | `-- anetos:no-transaction`, `-- anetos:no-split` |
| `ANETOS_*` environment variables | `ANETOS_*` |
| cookies `anetos_session`, `anetos_remember` | `anetos_session`, `anetos_remember` |
| default `APP_NAME` `anetos` | `anetos` |

### 1. Rename the module and imports

In `go.mod` (`require`, `replace` and `tool` lines, the driver and
plugin modules included) and in every Go and templ file, replace the module
path, then the test package and the package name:

```sh
grep -rlI --exclude-dir=.git 'anetos.dev/anetos' . | xargs sed -i 's#anetos.dev/anetos#anetos.dev/anetos#g'
grep -rlI --exclude-dir=.git -e anetostest -e 'anetos\.' . | xargs sed -i 's/anetostest/anetostest/g; s/\banetos\./anetos./g'
gofmt -w .
```

`gofmt` puts the imports back in order: `anetos.dev` sorts before
`github.com`. Scripts and docs that run `go tool anetos` now run
`go tool anetos`.

### 2. Directives

Old directives are plain comments now, so nothing warns about them:

- in models, `//anetos:model` and `//anetos:skip` become `//anetos:model`
  and `//anetos:skip`;
- in SQL migrations, `-- anetos:no-transaction` and `-- anetos:no-split`
  become `-- anetos:no-transaction` and `-- anetos:no-split`. Without
  the change, such a migration runs in a transaction, or split into
  statements.

### 3. Generated files

`anetos gen` only overwrites files it wrote. Delete the `models_gen.go`
files written by `anetos gen`, then run `go tool anetos gen`.

### 4. Settings

Rename `ANETOS_*` variables to `ANETOS_*` (tests: `ANETOS_TEST_*_URL`,
`ANETOS_AI_RECORD`). An app without `APP_NAME` was named `anetos`; set
`APP_NAME=anetos` to keep its cache, queue and session keys in Redis and
its default pub/sub subscription names (`<topic>.anetos`).

### 5. What doesn't carry over

The encryption key derivation and the signing contexts carry the
framework's name, so:

- values encrypted with the `encryption` package by v0.2, including under
  `APP_PREVIOUS_KEYS`, can't be decrypted. Decrypt them with the v0.2 build
  before upgrading and encrypt them again after;
- sessions, remember-me cookies, password-reset and email-verification
  links, and signed storage URLs issued by v0.2 are invalid: users sign in
  again and ask for new links;
- dead-letter messages carry `anetos.topic`, `anetos.subscription`,
  `anetos.error` and `anetos.attempts` (were `anetos.*`);
- the migration lock has a new name: don't run migrations from v0.2 and
  v0.3 binaries at the same time;
- temporary files a crashed write left on a local disk (`.anetos-tmp-…`)
  are listed like other files; delete them.
